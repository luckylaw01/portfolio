================================================================================
    FINGERPRINT-BASED ATTENDANCE SYSTEM (FBAS) - 3D SIMULATION PROJECT PLAN
================================================================================

OVERVIEW
--------
This project simulates the complete FBAS ecosystem including:
- The portable FBAS device (3D model with interactive touch screen)
- A simulated computer interface for setup and dashboard views
- Multiple case scenarios demonstrating real-world usage

The simulation will showcase how the device works in various contexts:
classroom attendance, teacher interactions, charging, device setup, and
administrative dashboard views.


================================================================================
DESIGN DECISIONS (Confirmed)
================================================================================

1. SCREEN INTERACTION: Option A - Click directly on 3D device screen
   - Camera auto-snaps to front-facing angle before screen interaction
   - More immersive experience
   - Orbit controls pause during screen interaction mode

2. FINGERPRINT SCAN: Sometimes fails (~2% failure rate)
   - Adds realism with occasional "Finger not recognized" errors
   - Shows error UI state and red LED flash
   - User can retry

3. COMPUTER MONITOR: Floating monitor with frame
   - Clean, minimal design
   - Just the monitor (no keyboard/mouse/desk)
   - Frame gives it physical presence in the 3D scene

4. DATA SCOPE: Large realistic dataset
   - 30+ students across multiple classes
   - 5+ classes/courses
   - Multiple teachers
   - Realistic Kenyan names and registration numbers

5. AUDIO: Yes - Sound effects included
   - Success beep on valid scan
   - Error buzz on failed scan
   - Button click sounds
   - Charging plug-in sound
   - Connection/sync sounds


================================================================================
DEVICE SPECIFICATIONS (Simulated)
================================================================================

Physical:
- Portable, handheld device
- Rechargeable battery (USB Type-C)
- Touch-enabled screen
- Fingerprint biometric sensor with LED ring
- Power button on right side

Connectivity:
- WiFi (internet connectivity)
- Bluetooth (for alternative setups)
- Can work offline with local storage

Data:
- Local storage for offline operation
- Syncs with central server when online
- Stores relevant teacher/class/student data locally


================================================================================
CASE SCENARIOS TO IMPLEMENT
================================================================================

SCENARIO 1: CLASS ATTENDANCE RECORDING
--------------------------------------
Description:
  The device is being passed around in class. Students place their fingers
  one by one to record attendance.

UI Elements:
  - Student list panel (floating HTML overlay on the side)
  - Student selector (click to simulate that student scanning)
  - Animated finger approaching and touching the sensor
  - Device screen updates with student info + SUCCESS message
  - LED ring animation (blue → green on success)
  - Audio feedback (optional beep sound)

Implementation:
  - Floating HTML panel with student list
  - Click student → finger animation plays → screen updates
  - Store attendance record in localStorage


SCENARIO 2: TEACHER CLASS SELECTION
-----------------------------------
Description:
  Teacher uses the touch screen to select which class they're teaching.
  They navigate through menus on the device screen.

UI Elements:
  - Device screen shows interactive menu (HTML overlay mapped to screen)
  - Class list view
  - Subject selection
  - Confirmation screen

Implementation:
  - HTML views that replace the device screen content
  - Views: Home → Classes → Select Class → Confirm → Ready for Attendance
  - "Pause Controls" button to disable orbit controls for screen interaction
  - "Reset View" button to snap camera to front-facing position


SCENARIO 3: CHARGING MODE
-------------------------
Description:
  Device is plugged in and charging.

UI Elements:
  - USB cable 3D model connected to the port
  - Charging indicator on screen (battery icon with animation)
  - LED ring shows charging state (pulsing orange/amber)

Implementation:
  - Toggle button to "plug in" the device
  - Animate cable appearing/connecting
  - Screen shows charging UI
  - LED ring color changes


SCENARIO 4: DEVICE SETUP (PAIRING WITH COMPUTER)
------------------------------------------------
Description:
  Initial setup where device pairs with the school's computer system.
  Shows both device and computer screen side by side.

UI Elements:
  - 3D computer monitor appears next to FBAS device
  - Computer screen shows pairing interface
  - Device screen shows pairing code/QR
  - Simulated wireless connection animation (particles/waves)
  - Step-by-step setup wizard on both screens

Implementation:
  - Add 3D computer monitor model to scene
  - Position camera to show both device and monitor
  - HTML overlays for both screens
  - Setup flow: 
    1. Computer: "Searching for devices..."
    2. Device: Shows pairing code
    3. Computer: "Device found - Enter code"
    4. Connection animation
    5. Computer: "Syncing data..."
    6. Both: "Setup complete"


SCENARIO 5: ADMIN DASHBOARD (COMPUTER ONLY)
-------------------------------------------
Description:
  Full computer interface showing the school's attendance system dashboard.

UI Elements:
  - Large computer monitor (or fullscreen)
  - Dashboard with:
    - Attendance statistics
    - Charts and graphs
    - Student management
    - Device management
    - Reports

Implementation:
  - Hide FBAS device, show only computer monitor
  - Full dashboard HTML interface
  - Multiple pages: Dashboard, Students, Teachers, Devices, Reports
  - Sample data visualization

================================================================================
AUDIO FILES TO GENERATE (Web Audio API / Oscillator)
================================================================================

All sounds will be generated programmatically using Web Audio API:

1. success_beep.js    - Short high-pitched beep (800Hz, 150ms)
2. error_buzz.js      - Low buzzer sound (200Hz, 300ms, slight distortion)
3. button_click.js    - Subtle click (white noise burst, 30ms)
4. plug_connect.js    - Satisfying click + subtle chime
5. sync_sound.js      - Soft ascending tones (data transfer feel)
6. power_on.js        - Rising tone sequence
7. power_off.js       - Falling tone sequence
